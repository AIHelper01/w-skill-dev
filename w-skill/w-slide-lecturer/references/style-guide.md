# Style and editorial rules

- Audience: international AI technology and application trainees.
- Spoken English: short clauses and familiar vocabulary; maintain correct technical terms (Self-Attention, ReAct, Plan-and-Solve, Reflection, Function Calling, MCP, Agent Skills, Context Engineering, Harness Engineering).
- Retain full original ideas; when original is awkward, make minimal grammatical corrections rather than rewriting from scratch.
- Use exact slides' top/left/right/bottom module order. Tables are read row by row; diagram flows follow arrows; do not conflate adjacent sections.
- Slide source = what learners see. Added lecture explanations = brief linking and grounding; separate clearly with bold vs ordinary text.
- Avoid invented or unsupported claims. Illustrative journeys, budgets and weather should be described as hypothetical classroom examples.
- Strong claims on slides can be qualified in a short non-bold sentence. Example: “prompts are not reusable” is a pedagogical simplification; templates can be reusable, but prompts alone cannot orchestrate complex workflows.
- Keep chapter introduction and thank-you scripts short. Avoid lengthy decorative conclusions or unrelated advice.
- If the user explicitly asks to merge, remove or reorder slides, preserve that decision and adapt transitions; do not refer to deleted slide content as still present.
- If the user requests full Word/Markdown export, first produce the complete scripts then export with clear slide headings and modules; never claim a document exists unless created.
