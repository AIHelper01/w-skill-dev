# 从网页提取指定演示

## 定位真实入口

获取用户给定页面的实际 HTML；结合截图、标题和控件识别目标，不默认选第一个 iframe。读取 iframe 的 `src`，按页面 URL 解析相对地址，必要时逐层跟进。如果服务端 HTML 不含目标，使用浏览器检查渲染后的 DOM 与资源请求。

常见情况是站点框架包裹一个自包含的自定义元素：真正的工具脚本、组件样式和 JSON 数据都在 frame 页面内。原页面地址可访问但某个读取工具失败时，可用正常 HTTP 下载或浏览器继续获取，不把单次工具失败当成目标不可用。

## 提取与资源处理

- 枚举实际执行的脚本、样式、图片、字体、数据、Worker、动态 import 和接口请求，区分教学功能与站点导航、统计上报。
- 优先保留原工具脚本和配置，不为了换样式重写算法或改变数据。
- 用 HTML 解析器定位元素，确保忽略 `<script>` 中的模板字符串。不要用宽泛的 `<mlcc-classification\b...` 正则提取：它也会匹配脚本中的 `<mlcc-classification-metrics>`。匹配完整标签名、真实属性，并核实提取结果起止位置。
- 单文件可把自包含的模块代码保留为内联 `<script type="module">`。外部模块经 `file://` 加载可能遭遇 CORS 限制；把路径改成本地并不等于可以双击运行。
- 如模块依赖复杂，选择合理的打包方式；不要用正则粗暴拼接 ES modules。处理相对 URL、CSS `url()`、动态加载、Worker 等引用。
- 去掉不必要的站点加载器、导航框架、外部字体及统计监听器；确认工具自身不再调用被移除的宿主 API。系统字体可作为离线替代。
- 必需资源确实需要本地服务时，提供最小可用启动方式并明确说明；若需要远端 API 才能计算，应说明限制，不能暗中以模拟结果替换原功能。

## 验证

用源页面中的已知初始状态核对数据量、选项和指标。初始值随机时不要断言固定数值，改为核对数据或范围。

操作实际可见控件，例如拖动滑块、用键盘调整原生 range、点击下拉选项。Shadow DOM 可用浏览器自动化的穿透定位器访问；如果只能用脚本派发内部事件，记录验证范围，不能据此声称鼠标拖动已测试。

确认图表、数值和选择状态同步变化；核对边界参数和切换数据集后的状态。检查屏幕宽度与截图，不下载无关的整个站点。
